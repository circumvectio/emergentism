## What now exists

[I] **Emergentism develops the instrument of reasoning; APU develops the instrument
for working with sources.** Emergentism is a demanding first library, not APU's
required worldview. APU's job is to make any admitted author's claims easier to
find, inspect, qualify and challenge. It must work just as honestly with a rival.

The owner-directed co-evolution is an explicit cycle:

`pin → question → retrieve → inspect → distinguish source gap from tool failure
→ route a proposal to its owner → separate adoption → test again`

[D] APU remains read-only. The new generic investigation desk preserves the
original question, every valid assisted query and miss, caller-declared assistance
provenance, dropped query terms, exact source ranges and whole-source inspections.
It generates no answer, adoption decision or authority. The CLI takes two explicit
JSON files and writes only stdout. This is not integrated into the normal browser
librarian and does not lock ordinary app projects read-only.

Code is locally committed in APU at **80098f2**. The strict passage engine was not
changed; gains below are assisted discovery, not improved unaided retrieval.
Contract: APU `apu.bot/docs/pilots/2026-09-06-investigation-desk.md`.
Frozen protocol/source commit: **00b39402**. Question-only query freeze:
**b092b833**, before retrieval and answer-key reveal.

## Complementary economic niches to test

| | Emergentism | APU |
|---|---|---|
| Primary job [I] | Help a reader articulate, compare and test a worldview or decision | Help a library user locate evidence, preserve conditions and prepare inspectable work |
| Owned artifact [D] | Corpus, distinctions, claim status, practice, research questions | Generic retrieval, source inspection, provenance and capability-limited tooling |
| Candidate value [C] | Clearer reasoning and sharper questions | Less time finding evidence and correcting unsupported answers |
| Failure signal | A distinction conceals a counterexample, ambiguity or unsupported inference | A relevant source is missed, an irrelevant hit seems authoritative, or a condition is lost |
| Does not own | The product runtime or proof of its own worldview by use | Canonical truth, user worldview, signing, publication or claim adoption |

[C] These are working job hypotheses, not discovered exhaustive market partitions.
No customer use, willingness to pay, economic value or comparative correction-time
gain was measured. Refine the niches against actual tasks: which question improved,
whose inspection burden fell, what artifact changed, who benefited, and what cost
or excluded alternative remained? Keep those observations separate from the
chosen worldview.

A retrieved passage can reveal an editorial defect; that does not make APU the
canon owner. A corpus clarification can improve a later search; that does not
prove the search engine improved. Change one axis per comparison and preserve the
old case. Each failure becomes development data, never a fresh test again.
