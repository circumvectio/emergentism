# The Launch Plan

> **The site is already live.** `emergentism.org` serves 391 pages and has been deploying
> to production all day. So *launch* here does not mean "make it public" — it means
> **make it worth arriving at**, and give the corpus a library a stranger can actually
> move around in.

## 0 · What is already done, so nobody rebuilds it

| | state |
|---|---|
| production deploy | live, `emergentism.org`, `READY` |
| pages | 391 routes, 0 missing `<title>` |
| publication boundary | deliberate: ~301 `noindex, follow` frozen library, ~43 current surfaces |
| sitemap | 45 entries, matching the current tier — **not a bug** |
| the ordered spine | **`reading-manifest.json` already lists 292 documents** with `section`, `title`, `href` |
| reader entry points | `/read/` 71 links · `/atlas/` 65 static links · `/book/` · `/compass/` · `/journey/` |
| gates | corpus 9 checkers, site 3, all green |

**The data for a library exists. The affordances do not.**

## 1 · The measured gaps

```text
client-side search        NONE          no index, no js, 391 pages
breadcrumbs               0 pages
prev / next chapter       1 page        on a 292-document ordered spine
og:image                  31 of 391     360 pages share as a bare link
persistent sidebar        inconsistent  152 files carry some toc/sidebar markup
```

Search is the single biggest one. A 391-page library with no search is a library with the
index torn out.

---

## SPRINT L1 · Search · *the biggest single win*

Build a static search index from `reading-manifest.json`'s 292 documents plus the current
surfaces, and a small client-side filter over it.

- `assets/search-index.json` — `{href, title, section, tier, snippet}` per document,
  generated by a script so it cannot drift from the manifest.
- `assets/js/search.js` — plain fetch + substring/token match, keyboard-first (`/` to
  focus, arrows, enter). **No CDN, no external font, no dependency** — the site already
  serves everything locally and should stay that way.
- Surface it in the topbar partial so it reaches the 392 pages that inline it.
- A generator check that fails when the index and the manifest disagree.
- **Exit condition:** typing three characters from any document title reaches that
  document, offline, with JavaScript as the only requirement.

## SPRINT L2 · Prev / next and breadcrumbs · *the spine already exists*

`reading-manifest.json` is ordered and sectioned. Nothing needs authoring — only rendering.

- Emit `← previous · section · next →` into each library page from the manifest order.
- Breadcrumb: `Emergentism / section / document`.
- Both generated, never hand-maintained, with a check that every document resolves.
- **Exit condition:** any library page can be left in either direction without returning
  to a hub, and 0 dangling prev/next targets.

## SPRINT L3 · Social cards · *360 pages, mechanical*

`assets/og/og-card.png` exists and 31 pages use it.

- Insert `og:image`, `og:title`, `og:description`, `twitter:card` into the remaining 360,
  derived from each page's existing `<title>` and meta description — both already present
  on every page.
- Per-section card variants only if cheap; a correct generic card beats 360 blanks.
- **Exit condition:** every route renders a card when pasted into a chat window.

## SPRINT L4 · The library shell · *consistency, not novelty*

152 files carry some sidebar or toc markup and it is not uniform.

- One shell: persistent section nav, current position highlighted, collapsed on mobile.
- Applied via the existing partial mechanism, not copied per page.
- **Exit condition:** the same navigation on every library page; `render_dimension_site.py
  --check` and the parity gate still green.

## SPRINT L5 · Launch QA · *the part that gets skipped*

Run it as a checklist, in a browser, not by reading HTML — this session was caught three
times by exactly that difference.

- mobile 375px and desktop: **no horizontal body scroll on any current surface**
- light and dark: the site commits to dark; confirm nothing is unreadable if a viewer
  forces light
- console clean on the ten current surfaces; no failed network requests
- `/404` and `/offline` behave
- the three site gates plus `check_record_counters` green
- **Exit condition:** a screenshot set of the ten current surfaces at two widths, attached
  to a receipt.

## SPRINT L6 · The launch act · *owner*

Not mine, and it needs one decision and one discipline.

- **The decision:** does the frozen library stay `noindex`? It is ~301 of 391 pages. Keeping
  it is defensible — *traverse but do not index* — but it means a launch surfaces about 43
  pages to search engines. That is a positioning choice, not a technical one.
- **The discipline:** the announcement copy is governed by the corpus's own trigger
  watchlist (`03_METHODOLOGY/00_THE_LENS_NOT_LAW_RULE.md`). No *unifies*, no *proves*, no
  *verified*, no named percentage without a receipt. A launch post that trips its own
  watchlist would be the most expensive possible first impression.
- **The one honest superlative available:** the site publishes 29 logged outcomes, 18 of
  them against the framework, all kept — and its own audit error rate. Lead with that
  rather than with the theory, because that is the part nobody else does.
- **Exit condition:** posted, and the URL recorded as a receipt.

---

## 2 · Sequencing

**L1 → L2 → L3 → L4 → L5 → L6.** Search first because it is the largest gap and everything
after it is cosmetic by comparison. L3 can run in parallel with anything — it touches only
`<head>`. L5 must be last and must be done in a browser.

L1–L5 are buildable in this session's style: generated from existing manifests, checked by
a script wired into the gate, mutation-tested. **None of them requires an owner decision.**
L6 requires two.

## 3 · What a launch does not do

It does not validate anything. On the framework's own conjunctive law the score stays 0
until an outcome returns from outside, and a launch is not an outcome — it is an invitation
to produce one. **The two plans are complements:** this one makes the invitation worth
opening; `00_THE_PROGRAM_PLAN.md` Sprint 1 is the invitation itself, and it is still unsent.

**Kill for this plan:** if L1–L5 close and a first-time reader still cannot find the
strongest page in the corpus in under thirty seconds, the plan optimised the wrong thing.
