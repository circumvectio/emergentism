# Local first, then an exact private GitHub delivery

## Direction amendment — 2026-09-10 [S/D]

The owner agreed to the website invitation plus atlas/workbench app described in
the [outline](01_OUTLINE.md). The initial packet was delivered separately; this
amendment is a local design record, not another delivery or implementation run.
The phases below remain gates, not permissions inferred from that agreement.

## 0. Complete the design packet — this task

[D] Create the outline, map it to existing owners, record current source/version
differences, review it independently, validate its structure and commit only its
files. Deliver only this packet to the established private Menexus branch. No
deployment, default-branch merge, corpus import or private-memory acceptance.

## 1. Produce the first complete reading slice

[D] Bind the six reader sections to a small, reviewed dependency set. Write the
executive explanation and the paired human/machine `EDD-DEMO-01` case selected in
the outline. Keep native definitions,
equations, qualifications and counterexamples intact. Choose an actual audience
and task before optimizing presentation. Follow the source-owned visual guide at
the later UI stage; do not rebuild the site just to choose an outline.

Before calling a source summary current, reconcile its trial-status drift in the
owning lane. In particular, the inspected machine manifest still describes MID-02
as unrun while its results exist; the earlier delivered entry contains the same
stale status alongside a results row. Preserve that finding, not the stale claim.
The reported self-correction case does not establish competitive superiority.

Exit: a reader can explain the lens, attempt the case, locate the source and name
what remains uncertain. Record assistance, sample size and observed failures;
these tasks have not been run by creating this plan.

### First experience slice — planned acceptance, not results [D]

Before expanding the UI, connect the executive explanation, one source-bound
atlas panel (the D4/D5 distinction) and the selected `EDD-DEMO-01` scenario.
Keep this a development demonstration, never relabel it a held-out evaluation.

- A newcomer can go from the invitation to Explore or directly to Apply.
- The panel preserves its native definitions, source version, tier, qualification
  and correction route; D5 representation is not an execution permission.
- The same question moves through human and machine views without losing facts,
  uncertainty, rivals, affected bearers, the proposed test or the revision point.
- A result is labeled unobserved until evidence is supplied. Compare the case
  with the same plain decision journal and preserve any simpler-method advantage.
- Accountless public inspection, keyboard access, a static/reduced-motion
  alternative, source inspection and Exit work without optional model services.
- Saved/private work, inference, sharing and execution are not silently enabled
  by opening the atlas or following the walkthrough.

Content review precedes UI construction. Record the actual test, audience, sample
size, assistance and failures when run; checking this plan measures none of them.

## 2. Qualify a portable instrument edition

[D] Complete three source-safe case families from the outline, including failure
and abstention. Bind supported machine inputs/outputs to existing contracts. Run
the applicable parser, schema, fidelity, source, rights and portability checks.
Compare the declared task with plain documents/search and a simpler checklist;
retain a superior simpler approach rather than changing the scoring afterward.

Release packet: exact version and source selection, human guide, existing-format
machine artifacts, worked cases, limitations, test results, licence/rights scope,
export instructions and change history. These are future deliverables, not
contents implied by the current design packet.

## 3. Improve APU and Menexus from real use — a parallel, gated workstream

[D] Finish the existing one-source/five-proposal private review before broadening
private intake. Each corpus batch can yield a source improvement proposal, an APU
reproducer and a Menexus reproducer. Test each product in its own repository with
pinned versions and preserved predecessors. No automatic source adoption,
acceptance, policy promotion or source upload follows from a successful check.

Connected qualification requires real admission, review, correction, renewed
disclosure and export/Exit tests. The portable edition does not depend on these
features being live. Never simulate the owner's review or use a reviewer token.

## 4. Expand through the whole corpus

[D] Work dependency-first: controls and kernel → formal/register distinctions →
agency and value → Rosetta and carrier maps → research and synthesis → public
projections → historical remainder → edition reconciliation. A later dependency
may be pulled forward explicitly for the first release; count it once and reopen
it on material change. Relevant counterexamples and corrections travel with each
claim, not only when the archive phase arrives.

Initial batch cap: five primary source files/section units, ten useful claim
proposals and 15,000 source words, whichever is reached first. These are proposed
workload limits. Preserve complete argument/qualification windows and record any
unread range. Every path is accounted for; protected or inaccessible material is
not secretly read or counted as reviewed. Estimate delivery time after three
measured batches rather than from file count.

## 5. Public projection is a separate release

[D] Only an explicitly selected, rights-cleared edition enters website/RAG/PWA
generation. Preserve static reading, accessibility and private/public cache
separation. Run the applicable source, semantic, deterministic-artifact and
predeploy gates. Private GitHub delivery is not website deployment or evidence
that the instrument improves decisions.

## Completion states

| State | Meaning |
|---|---|
| Design prepared | This outline and its bindings passed bounded structural review |
| Private GitHub delivered | Exact packet blobs and remote commit were verified |
| Content ready | Selected explanations, cases and qualifications passed their declared review |
| Portable instrument qualified | The declared artifact/workflow tests passed locally |
| Connected feature qualified | The specific APU/Menexus integration passed its separate tests |
| Published/deployed | An authorized public delivery was performed and verified |

Do not collapse these states into one “done.” This packet promises none of the
later states merely by existing.
