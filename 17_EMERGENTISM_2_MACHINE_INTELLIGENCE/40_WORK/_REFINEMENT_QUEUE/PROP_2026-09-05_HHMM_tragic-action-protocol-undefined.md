# PROP — The tragic-action protocol is referenced but never defined

## The surface (quoted verbatim)

§8 (Power-Max):

> If `A_J` is empty, use the tragic-action protocol; do not manufacture a
> maximum.

§4 (no aggregate laundering):

> If a conflict cannot be resolved without violating the envelope, the model
> returns **no admissible action**, not permission to choose the least visible
> victim.

## The observation [I]

The framework is explicit and correct: when `A_J` is empty — when every
available action violates the Justice envelope for some bearer — the answer is
"no admissible action," not "pick the least harmful." This is honest and
anti-utilitarian. It refuses aggregate laundering and refuses to hide the
least-visible victim.

But the framework then says "use the tragic-action protocol" **without defining
what that protocol is**. This is the ethics equivalent of a declared-but-
unimplemented function. The framework's hardest cases — where every action
causes real harm to a real bearer — are exactly the cases where an ethics must
provide the most guidance. The framework provides none. It names a protocol and
moves on.

The Wigner audit (from the 2.0 stack) would classify this as:
**warrant-substitution** — evidence-of-checking published as warrant. The
phrase "use the tragic-action protocol" *names* a response, but since no
protocol is defined, it substitutes naming for guidance.

## Why this matters

In real ethics, the hard cases are the ones where Justice cannot be satisfied
for every bearer. A triage doctor, a judge in a custody dispute, a leader in a
resource-scarce organization — these agents *must act*, and every action
harms someone. The framework correctly says "don't launder the harm" but
then goes silent on what to do instead.

The absence of a tragic-action protocol means the framework is strongest
exactly where ethics is easiest (whenJustice is satisfiable) and weakest
exactly where it is hardest (when Justice is impossible). This is not a
theoretical concern — it is the primary operational gap.

## The proposed refinement

Define the tragic-action protocol. At minimum, it should specify:

1. **Acknowledgment** — the agent names which bearers' Justice envelopes are
   violated and by how much
2. **Minimization** — among available actions, the agent selects the one that
   violates the fewest envelopes by the smallest margin (not the same as
   choosing the least visible victim, because the violations are named and
   counted, not hidden)
3. **Proportionality** — the violation must be proportional to the necessity
   (a triage doctor's violation is proportional to the medical emergency)
4. **Repair** — the agent commits to repair the violated bearer's position
   when feasible, after the urgent action
5. **Non-normalization** — the violation is recorded as a violation; it is
   never re-described as acceptable, heroic, or optimal

The protocol is NOT utilitarian (it does not sum harms), NOT absolutist (it
does not refuse to act), and NOT covert (it names every violation openly).
It is a **tragedy accounting protocol** — the moral equivalent of the
framework's own dual option ledger, applied to the case where every option
harms.
