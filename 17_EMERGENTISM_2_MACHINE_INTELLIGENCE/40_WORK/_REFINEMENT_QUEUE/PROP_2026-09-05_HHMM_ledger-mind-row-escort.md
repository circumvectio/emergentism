# PROP — The ledger's mind-at-D4 row should cite CASE-01

## The finding

Section C of the founding ledger includes: **mind is D4** — placing it in D5
fires a registered falsifier. This is the ledger's strongest negative result
about machine intelligence. It has now been formally confirmed:

- **CASE-01** (`20_CHECKS/CASE_01_MIND_AT_D5_2026_09_04.md`) adjudicated the
  owner's own claim that mind crosses into D5. Verdict: **ILL_TYPED** — mind
  and body are both D4; there is no lift to type. The ADJ-01 operator's
  same-register halt fires. 9/9 tests green.
- The confirmation was committed in the same git sequence as the ledger's
  update (`a7cc4296`) but the ledger does not cite the case.

## The refinement

Add to Section C's mind row (or as a footnote): *"Formally confirmed by
CASE-01 (20_CHECKS/CASE_01_MIND_AT_D5_2026_09_04.md), verdict ILL_TYPED,
2026-09-04."*

This is the kernel's own escorted-number check applied to a negative result:
the claim travels; the producing case should travel with it.

## dies_if

This proposal dies if: the ledger's Section C is intentionally uncited because
Section C rows are *established negatives* that predate their confirmations —
in which case the confirmations belong in a separate "confirmed by" column, not
in the prose. But the escorted-number principle still applies: a negative
result that has been formally tested should carry the test's reference.
