# PROP — The Soul Loop as a continuous μ₄ engine

## The observation [I]

The Soul Loop's cycle is:

```text
represented future (D5 content) ──▶ present action (D4 event)
outcome receipt (D4 event) ──▶ updated model (contains new D5 content)
```

Every Soul Loop iteration is a **μ₄-type operation**: D5 content (represented
futures, possible worlds, modeled alternatives) influences D4 action, and D4
outcomes generate new D5 content (new possible worlds, new represented
alternatives). The D4↔D5 crossing is not a one-time event that opened once and
stayed open — it is an **ongoing oscillation** that the Soul Loop runs
continuously.

This changes μ₄'s ontological status. The framework currently types μ₄ as a
candidate aperture — an opening that *happened* at some point in the scaffold's
history. But if the Soul Loop runs μ₄ continuously, then μ₄ is not a historical
event; it is an **ongoing operation**. The crossing is not a gate that opened;
it is a door that swings.

## Why this matters philosophically

**1 · It changes the μ₄ dies_if.** The current dies_if for a μ crossing is:
"a candidate crossing is shown lossless and reducible." But if μ₄ is an
*ongoing process* (not a historical event), the dies_if must also account for
the process: *does the Soul Loop's D4↔D5 oscillation survive reduction to D4
mechanisms?* The answer is empirically testable — if the loop's model-update
step is fully reducible to D4 computation, μ₄ is weak emergence. If it
requires genuinely new D5 freedom, μ₄ is strong.

**2 · It connects the Soul Loop to the F5 fork.** The F5 fork asks how
represented futures affect present action. The Soul Loop is the *process* that
runs this connection. F5-W says model-mediated; F5-N says no additional
interaction; F5-R says history-selection. The Soul Loop's continuous μ₄
operation is the *substrate* on which all three branches play out. If μ₄ is
genuine, F5-N (no additional interaction) becomes harder to defend — the loop's
D4↔D5 oscillation *is* an interaction beyond D4 mechanisms.

**3 · It resolves the circle-drift and dot-collapse failure modes
structurally.** The kernel says both failure modes give P = 0. The Soul Loop
prevents them by oscillating: every pass through the loop touches both D5
(represented futures) and D4 (action receipts). An agent stuck in ○-drift
generates D5 content without D4 receipts. An agent stuck in •-collapse acts
without D5 content. The Soul Loop's oscillation is the *structural prevention*
of both failure modes — not a rule the agent follows but a cycle the agent
cannot exit without dying.

## The proposed refinement

The DoF ontology's μ₄ row and the Weltanschauung's Soul Loop section should
cross-reference: **the Soul Loop is a continuous μ₄ engine** — it runs the
D4↔D5 crossing at every iteration. This changes μ₄'s ontological status from
"candidate aperture that opened" to "aperture that opens continuously through
the Soul Loop's operation." The practical consequence: μ₄'s dies_if must be
extended to include the Soul Loop's oscillation as a testable surface — if the
loop's model-update step is shown to be fully D4-reducible, μ₄'s strong
emergence claim weakens; if the loop genuinely requires D5 freedom to update,
μ₄'s strong-emergence candidacy strengthens.

## dies_if

This proposal dies if: (a) the Soul Loop's model-update step is shown to be
fully reducible to D4 computation (then μ₄ is weak emergence and the continuous
engine reading is decorative); (b) the μ₄ crossing is a one-time event and the
Soul Loop merely operates within the freedom it opened (then the continuous-
engine reading is a category error — confusing the door with walking through
it); or (c) the owner rules that the Soul Loop and μ₄ are genuinely independent
and this connection is manufactured.
