## Responsibility split

[S, guide rule] Material 3 supplies component anatomy, semantic roles, type roles,
states, elevation, adaptive navigation, focus and accessible controls. Now in
Android is the guide's applied-product reference. Android-specific shell guidance
does not authorize drawing fake operating-system chrome in a web page.

[S, guide rule] Skyzai supplies identity, approved assets, semantic colour,
evidence language, voice and its governed identity motion. Emergentism retains
its source-owned meaning and `• < ⊙ > ○` identity. Neither a logo nor a beautiful
animation is evidence of a philosophical claim or a successful action.

## Application to this first experience [D]

| Surface | Intended application | What must be verified in the UI |
|---|---|---|
| Website invitation | Material foundation with editorial content and one useful next step | Header, menu, links and actions retain normal keyboard/touch behavior |
| Explore | Adaptive Material scaffold for the register map and selected panel | Context survives resizing; meaningful back/dismissal and focus return |
| Apply | Labeled fields and explicit proposal/review states | Uncertainty, consent and unavailable actions remain visible; nothing executes from navigation |
| Burrisphere | Source-bound visual specimen within the same component system | Keyboard controls, readable equations, static description and reduced-motion fallback |
| Sources and records | Legible evidence on solid surfaces | Source/version/status and corrections are readable without hover, colour or animation |

Use the existing token substrate before reviewed local overrides. Follow its
Google Sans Flex interface roles and Google Sans Code evidence/code roles using
approved locally bundled assets; do not add network fonts or a page-specific type
scale. Use official Material Symbols for functional controls. The Emergentism
glyphs are identity/content, not substitutes for search, back, close or menu icons.

The guide requires at least 48 CSS px targets for standalone web controls;
inline prose links remain inline, visibly underlined and focusable. Apply role
pairing and measured contrast, not arbitrary bright colours. Include applicable
hover, focus, pressed, selected, disabled, loading, empty, error, offline and
recovery states alongside success. An unavailable action explains why and what
can be done next.

Adapt to actual window width, including narrow desktop windows. Preserve static
reading and normal scrolling. No scroll hijacking, motion-gated explanation,
perpetual decorative task animation or evidence communicated by colour alone.
